Start in three steps

  1. Sign in. Use the account you were given, or create one on the sign-in page.
  2. Check your Arcade key. The chip in the top bar says whose key is in use. If a company key is set up you can start right away. Otherwise click the chip, paste your own from Arcade Studio, and press Save and test.
  3. Pick a workflow. A blank bench asks what you want to make. Click "Jewelry from a prompt", choose your options in the side panel, and press Run flow.

The bench

The bench is a canvas. Each box is a step, and each step is one thing the Arcade API can do. Wires carry a step's result to the next step.

  • Start from a workflow. A blank bench offers whole workflows. One click lays out every step.
  • Add a step. Press Add a step, then click or drag one from the list.
  • Set a step up. Click a step and its side panel opens. Categories are picture tiles, metals and product options are chips, and anything Arcade can't make is struck through.
  • Wire steps. Drag from a dot on the right edge of one step to a dot on the left edge of another. Click a wire, then its cross, to remove it.
  • Run. Run on a step runs that step, and any step before it that has no result yet. Run flow runs every step that has not worked yet, one at a time.
  • Read the status. Ready, Can't run, Running, Worked or Failed. A step that can't run tells you why before you spend a generation.
  • Fork. Fork copies a step and everything after it, fed by the same inputs. Change the copy and run it to compare two versions.
  • Inspect. The same panel shows the step's result, Arcade's rules for it, and every request and raw response.
  • Check the flow. Click the step counts in the top bar to see every step's status in one list.
  • Undo. Ctrl+Z (Cmd+Z on a Mac) undoes the last change to the flow: a step added or removed, a wire, a move, a setting. Ctrl+Shift+Z or Ctrl+Y redoes it. Results a step has made are never undone. More shortcuts are listed under More, Keyboard shortcuts.
  • Keep flows. Flows save to your account as you work. The flow menu opens, duplicates and deletes them. Under More, Export and Import move a flow as a JSON file.

What Arcade allows

Every category is either print or jewelry. That one fact decides most of what can follow.

StepPrintJewelry
DesignPrompt, plus optional style model and colors. Works with or without a category.Prompt only, and a category is required. One call makes the piece and its product.
Refine (edit, recolor, crop, seamless, extend, fix)Yes. Each refine makes a new design.Refused with 400. Fork the Design step and change the prompt instead.
Build productYes. Choose options, or let Arcade pick.Refused. The Design step already made the product.
PriceYes.Yes.
Checkout linkYes.Yes.
  • Name the metal. A jewelry prompt should name one metal the category offers. Run the Category step to see the list.
  • Say "no stones" when you mean it. Arcade may add a stone to a plain piece, and that raises the price.
  • A jewelry job can fail on price. If no maker can price the design, try another metal or a simpler shape.
  • Quantity 1 needs drop-ship unless the account has a subscription. Otherwise checkout returns 412.
  • Checkouts are real. The workbench asks before creating one and never pays. Nothing is charged until someone pays on Arcade's page.
  • Not available: upscale (Arcade Studio only), region edits and reference images (not built into the bench yet).

Listing in your own store

The "List in a store" step adds a product to a WooCommerce or Shopify store. Connect the store from the step's Store list: its address and its API keys. Set your own price; anything above Arcade's price is your margin. The listing is a draft unless you tick the box. Orders placed in your store are not sent to Arcade automatically: for each one, make a Checkout link here and pay Arcade, and it ships to your buyer.

Runs

Every step you run is recorded. The Runs page shows the success rate, counts of worked and failed runs, the same numbers per step and per flow, the typical time a step takes, and the reasons steps failed. Use it to see which steps are reliable before you build on them.

Models and keys

  • On the bench. Two chips in the top bar show the Arcade key and the AI model. Click either one for a small box: choose the company key or your own, paste a key if it is yours, and press Save and test.
  • Claude, OpenAI and Gemini are ready. All three are fully set up. A key is the only thing you add.
  • Company key or your own. The company key is one the workbench's owner has set up for everyone. Your own key is used only for your account.
  • Choose the model. Once a key works, the box lists the text models on it, read live from the provider. Image and audio models are left out until a step needs them.
  • Other models. The Models and keys page also connects OpenRouter, Groq, a local Ollama, or any service that speaks the OpenAI chat format, with every setting open to change.
  • Load the model list. After saving a key, press Load models from the provider and pick one. You can also type a model ID.
  • Test it there. The side panel sends one real request and shows the reply, the time it took, or the provider's error.
  • Where keys go. Keys are encrypted on the server and never sent back to the browser. The page only shows the first and last characters.

API watch

The server checks on its own, every six hours, whether the APIs it depends on have changed. It reads Arcade's published API description, the list of Arcade's documentation pages, and each model maker's live model list, compares them with the last check, and lists what is new, gone or different on the Models and keys page. If a ready-made model is retired, connections on the company key move to the best one left. Makers with no company key are checked when someone presses Check now with their own key connected.

Prompts

  • Save prompts that work on the Prompts page, marked for jewelry, print or either.
  • Ask a model for ideas. Pick a connected model and a category, add a few words, and press Suggest prompts. The model is given Arcade's rules, so the ideas name a metal the category can be made in.
  • Pick the model in place. The Model list sits next to the idea box. Its last entry adds an API key or changes the model without leaving the page, and a tick box makes the chosen model your default.
  • Use them on the bench. The Design step's panel has two buttons near its prompt. From library picks a saved prompt. Suggest a prompt has the model write one straight into the box, using whatever you had typed as the idea; press it again for another.

Data

Flows, run history, prompts and connections are rows in one SQLite database, stored per account. The Data page shows where the file is and lets you download everything of yours as JSON. The admin can point the workbench at a different SQLite file there. Postgres and hosted databases are not supported yet.

Hosting it for other people

Out of the box the server listens on this machine only. Before anyone else can reach it, set these in .env:

WORKBENCH_USERS=yourname:a-long-password   # first one is the admin
WORKBENCH_SECRET=a-long-random-string      # encrypts stored API keys
ALLOW_SIGNUP=false                         # or leave on to let people create accounts
SHARE_HOST_KEYS=false                      # or leave on to lend your keys to everyone who signs in
  • The sign-in is a light one. It is a name and a password, with no email, reset or second factor. Put the server behind HTTPS and your own access control before exposing it.
  • Sharing host keys means sharing the bill. Anyone who signs in can create designs and checkouts on that Arcade account.
  • Custom model URLs are called from the server. Only give accounts to people you trust with that.

Add a capability

Each capability is one entry in public/nodes.js: its inputs and outputs, its fields, the rules that decide whether it can run, and the calls it makes.

add('price', {
  title: 'Price', group: 'Product', endpoint: 'products/get', worlds: ['print', 'jewelry'], cost: 'read',
  blurb: 'Reads the guaranteed unit price, maker and images for a quantity.',
  inputs: [{ key: 'product', type: 'product', label: 'Product' }],
  outputs: [{ key: 'product', type: 'product', label: 'Product' }],
  fields: [{ key: 'quantity', kind: 'number', label: 'Quantity', default: 1, min: 1 }],
  check: (n, g) => [],            // return { level: 'block', text } to stop it, with the reason
  run: async (n, inp, ctx) => ({ product: await ctx.readProduct(inp.product.productId, n.cfg.quantity) }),
});

If the capability calls an Arcade endpoint that is not listed yet, add it to the allow-list in server.js.
